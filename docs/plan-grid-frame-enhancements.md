# 作業計画: 初期モデル生成(グリッドフレーム)の拡張 — モデル簡易設定の追加機能

作成日: 2026-07-19

前提: PR #56(初期モデル生成: 階高・スパンリストから柱・梁グリッドフレームを一括生成)がマージ済み。
本計画はその生成ダイアログを「モデル簡易設定」の入口として育てるための追加機能をまとめる。
元計画 `docs/plan-initial-grid-frame.md` の §6(初期スコープ外)を出発点に、現行コードの調査結果で裏付けた。

## 1. 候補機能一覧

| # | 機能 | 概要 | 効果 | コスト | 優先度 |
|---|------|------|------|--------|--------|
| 1 | 繰り返し記法 `N@L` | スパン・階高入力で `3@6000, 5000` のような繰り返し指定を許容 | 等スパンの入力が大幅に短縮(実務で最頻) | 小 | ★★★ |
| 2 | 断面の一括指定 | 生成ダイアログに柱断面・梁断面のセレクトを追加し、生成部材へ適用 | 生成後の断面一括変更作業が不要になる | 中 | ★★★ |
| 3 | 床(スラブ)自動生成 | チェックボックスで各階・各スパン区画に `floor` 面材を生成 | 床入力の反復作業を排除。数量集計・荷重入力の下地になる | 中 | ★★★ |
| 4 | 入力値の永続化+プリセット | 入力値を localStorage に保存し、リロード後も復元。定型プリセットの保存/呼出 | 同じ建物型式を繰り返し試す用途で有効 | 小〜中 | ★★☆ |
| 5 | 外周ブレース自動生成 | チェックボックスで外周構面の指定スパンに垂直ブレース(vbrace)を生成 | ブレース構造の初期モデルが一発で立つ | 中 | ★☆☆ |
| 6 | 通り芯命名オプション | Y 方向を `A, B, C…` にする等の命名規則選択 | 実務の通り芯表記に一致 | 小 | ★☆☆ |
| 7 | 既存モデルへの追加生成 | 置換ではなくマージ、基準点(原点以外)指定 | 増築・別棟の入力 | 大 | 今回外 |

**推奨スコープ: #1〜#4 を本計画で実装**。#5・#6 は本計画の構造に乗るので余力があれば追加、#7 は
節点共有・ID 衝突・通り芯重複の設計が別物になるためスコープ外(§7)。

## 2. 既存コードの前提(調査結果)

- **繰り返し記法**: 入力パースは `parseMmList`(`js/frame-generator.js:17-35`)に一元化済み。トークン分割
  (`/[,、\s]+/u`)の後段に `N@L` 展開を挟むだけで UI・生成ロジック両方に効く。展開後に既存の
  `maxCount` / 範囲チェックがそのまま働く
- **断面指定**: `addMember` は `options.sectionName` を受け取り、`_ensureMemberSection` が
  カタログ照合 → type 既定 → 同 type 任意、の順でフォールバックする(`js/state.js:855-901`, `664-688`)。
  つまり生成側は `sectionName` を素通しするだけでよく、不正名でも安全側に落ちる。
  カタログ列挙は `state.sectionCatalog`(`target==='member'`, `type==='column'|'beam'`)、既定名は
  `getDefaultSectionName('member', type)`。ただし buildGridFrame は `new AppState()`(既定カタログ)に
  組み立てるため、**現在モデルのユーザー定義断面を使うには生成モデルへのカタログ引き継ぎが必要**(§3.2)
- **床面材**: `addSurfaceRect(x1, y1, x2, y2, { type, levelId })` があり、`type: 'floor'` は既定値
  (`js/state.js:1080-1100`)。面材断面も `_ensureSurfaceSection` が既定を補う。サンプル
  (`js/samples.js`)に床生成の先例があるか実装時に確認し、あれば規約(levelId の階、頂点順)を踏襲
- **ブレース**: member type `vbrace` + `bracePattern: 'single'|'cross'`(`js/state.js:890`,
  `js/tools.js:705` 付近)。柱と同じく `levelId`/`topLevelId` で層を表現するはず — 実装時に tools.js の
  作図フローで属性の組み合わせを確認してから生成コードを書く
- **永続化**: localStorage の先例は theme(`js/app.js:579`)、言語(`js/i18n.js:882`)、autosave
  (`js/autosave.js`)、パネル幅(`js/side-panels.js:55`)。キー命名は `lineframe-*` 規約
- **ダイアログ**: `js/grid-frame-modal.js` の `fields` 配列(storyHeights/spansX/spansY)が入力欄を
  駆動しており、欄の追加はここに乗る。入力値はモジュール内変数で保持(セッション内のみ)
- **テスト**: 純ロジックは `test/frame-generator.test.js`、UI は `test/grid-frame-ui.test.js` の
  fake DOM 方式(`withFakeBrowser`)が雛形。i18n は ja/en 同時追加(`test/i18n-parity.test.js` が強制)

## 3. 仕様詳細

### 3.1 繰り返し記法 `N@L`(#1)

- `parseMmList` を拡張: トークンが `/^(\d+)@(.+)$/` に一致したら `N` 個の `L` に展開
  - `N` は 1〜maxCount の整数。`L` は既存の数値チェックをそのまま適用
  - 展開**後**の個数で `maxCount` 判定(`3@6000, 5000` → 4 要素)
  - 不正な `N`(0、小数、負)や `@` の多重出現は `reason: 'invalid'`
- プレースホルダ・ヘルプに記法例を追記(例: `3@6000, 5000`)
- 既存呼び出し側の変更は不要(戻り値形式は不変)

### 3.2 断面の一括指定(#2)

- ダイアログに「柱断面」「梁断面」セレクトを追加。選択肢は**現在モデル**の
  `sectionCatalog`(member/column、member/beam)から表示時に構築し、初期選択は
  `getDefaultSectionName` の既定断面。「(既定)」相当の未指定選択肢は設けず、常に明示選択とする
- `buildGridFrame({ ..., columnSection, beamSection, sectionCatalog })` に拡張:
  - `sectionCatalog` が渡されたら生成側 AppState のカタログを置き換え(`toJSON`/`loadJSON` の
    カタログ直列化仕様を確認の上、`hydrateSectionCatalog` を利用)
  - 柱・梁の `addMember` に `sectionName` を渡す。未知名はフォールバックに任せる(例外にしない)
- これによりユーザー定義断面が生成モデルに引き継がれる(現在モデル置換後もカタログが残る)

### 3.3 床(スラブ)自動生成(#3)

- ダイアログに「床を生成する」チェックボックス(既定: OFF。既存挙動を変えない)
- ON のとき GL を除く各レベルで、各スパン区画(sx × sy 個)に
  `addSurfaceRect(x1, y1, x2, y2, { type: 'floor', levelId })` を実行
- 面材数 = sx × sy × s。**部材数上限とは別に合計要素数のガードを再計算**:
  `MAX_GRID_FRAME_MEMBERS` の判定を「部材+面材」合計に変更するか、面材用上限を別途設ける
  (エラーメッセージの count/max 表示は既存の仕組みを流用)
- 完了通知に面材数を追記(例: 「柱{c}・梁{b}・床{f}」)

### 3.4 入力値の永続化+プリセット(#4)

- **永続化**: 生成成功時に入力値(+断面選択・床チェック)を
  `localStorage('lineframe-grid-frame-input')` へ保存し、モーダル初期化時に復元。
  破損 JSON は無視(autosave.js の try/catch パターン踏襲)
- **プリセット**: 同キー空間 `lineframe-grid-frame-presets` に名前付きで保存/呼出/削除。
  UI はダイアログ上部にセレクト+「保存」「削除」ボタンの最小構成。件数上限 20
- 保存対象はあくまで入力文字列(パース前)とし、呼出時に通常のバリデーションを通す

### 3.5 外周ブレース自動生成(#5・任意)

- 「外周にブレースを配置」チェック+パターン選択(シングル/襷掛け)
- 外周 4 構面の各スパン × 各層に vbrace を生成(隅スパンの重複配置に注意)
- 属性の正解(startZ/endZ・topLevelId の要否)は tools.js の作図結果を先に観察して決める

### 3.6 通り芯命名オプション(#6・任意)

- 「Y 通り名: Y1,Y2,… / A,B,C,…」のトグル。`buildGridFrame` にオプション追加。
  27 本以上は `AA, AB…` 方式

## 5. 影響範囲・注意点

- 既存の生成フロー(`history.save()` → `loadJSON` → UI 再同期)は変更しない。全機能とも
  「生成モデルの中身」と「ダイアログ入力」の拡張であり、undo/redo・autosave にそのまま乗る
- 既定値はすべて現状維持(床 OFF、断面は既定断面)— 既存テスト・既存ユーザーの体験を壊さない
- カタログ引き継ぎ(§3.2)は `toJSON`/`loadJSON` のカタログ直列化を跨ぐため、往復テストを必ず書く
- 上限ガード(§3.3)の変更時は、エラーメッセージの `{count}/{max}` 表示(i18n 補間)との整合を保つ
- i18n は ja/en 同時追加を厳守(`test/i18n-parity.test.js`)

## 6. スコープ外(将来)

  (`mergeNearbyNodes` の流用可否)、置換確認 UI との整合など設計が別物。必要になった時点で別計画を起こす

- スパン非直交グリッド・セットバック(階ごとに平面が異なる)対応
