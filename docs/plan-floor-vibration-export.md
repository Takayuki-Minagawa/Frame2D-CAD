# 作業計画: 床振動検討向け解析エクスポート強化

作成日: 2026-08-08

出典: `床検討/` の分析資料 2 点
- `260808_床振動・TMD検討_手順とプログラム構成_解析プログラム対応版.html`
- `260808_床振動解析プログラム_追加機能・参照資料マトリクス.html`

分析資料は element-modeler / Beam-TrussStructMaker / FEM-Struct-PyGo /
FloorModeAnime / FloorModal / FloorVIb-TMD-Opt の 6 プログラム構成を監査し、
床振動・TMD 検討を一気通貫で回すための追加機能バックログ(P0〜P2)を定義している。
本計画は、そのうち **element-modeler(本プログラム)が担当する範囲**を抽出し、
実装単位に分解したもの。

## 1. 分析資料からの抽出結果

element-modeler の責務は「幾何編集フロントエンド」であり、床メッシュ生成・
SI 単位変換・解析実行は下流(adapter / Beam-TrussStructMaker)の担当。
その境界を保った上で、資料が element-modeler に求める事項は次のとおり。

| 資料の指摘 | 該当バックログ | 優先 | 本計画での対応 |
|---|---|---|---|
| 要素 ID が文字列(`M1` 等)で、下流の数値 ID 前提と衝突(NaN・重複判定) | INT-02 | P0 | A: 数値 ID 採番+元 ID 保持 |
| 来歴(生成器・版・日時)・座標系宣言・節点順の明示がない | INT-01 | P0 | B: manifest 対応メタデータ |
| 材料 E・G・密度がエクスポートされない | INT-02 | P0 | C: 材料物性カタログ |
| 断面特性 A・I・J がなく b/h のみ | INT-02 | P0 | C: 断面特性の算定・出力 |
| ばねが記号+メモのみで実剛性値がない | INT-02 | P0 | D: ばね剛性値 |
| 自重・仕上げ・積載の質量源情報がない | INT-02 | P0 | E: 質量換算メタデータ |
| 対象階・床面区画の識別情報が不足 | INT-02/INT-03 | P1 | F: 床区画情報 |
| 出力名 `*_analysis_*.json` が下流ビューアの自動判定と不一致 | INT-02 | P0 | B: format 識別子の明確化 |

スコープ外(責務境界により下流が担当):
- 床面の解析メッシュ生成、有効幅・直交異方性・合成/非合成の設定 → adapter/Beam
- mm→m の SI 正規化の実施 → adapter(本計画では変換に必要な単位宣言までを担当)
- 固有値解析・歩行応答・評価・TMD → FEM-Struct 以降

## 2. 追加機能の概要

### A. 解析エクスポート v2: 数値 ID + 元 ID 保持(P0)

- `ANALYSIS_FORMAT_VERSION` を 2 に上げる。
- 要素・支点・荷重の `id` を **1 始まりの連番数値**で採番し、CAD 上の
  元 ID(`M1`、`M12X` 等)を `sourceId` として全行に保持する。
- X ブレースの 2 本目(現状 `${id}X`)も独立した数値 ID を持ち、
  `sourceId` は共通の元部材 ID+枝番情報で往復可能にする。
- 受入条件(資料 INT-02 より): `M1`/`M2` を含む例が **重複なく**変換でき、
  数値 ID→元 ID の対応が一意に復元できること。

### B. manifest 対応メタデータ(P0)

資料 §4「共通交換仕様案」の project manifest(floorvib-project/1)へ
element-modeler 出力を接続するための最小メタデータを `meta` に追加する。

- `generator`: `{ name: 'element-modeler', formatVersion, appVersion }`
- `generatedAt`: ISO 8601 タイムスタンプ
- `coordinates`: `{ verticalAxis: 'z', handedness: 'right' }`
- `units` に `mass` 換算の前提(§E)と各量の元単位を明示(既存 units block を拡張)
- 節点は現状どおり採番順の配列だが、**節点順が ID 順であることを仕様として明記**
  し、下流の `node_order_hash` 計算の前提を固定する。

ファイル名は既存の `*_analysis_*.json` を維持しつつ、`format` /
`version` フィールドでの識別を正とする(下流の自動判定はファイル名でなく
`format` を見る契約とし、README に明記)。

### C. 材料物性・断面特性(P0)

床モード解析には E・G・ρ と A・I・J が必須(資料 p.7「床の物理化」)。

- **材料カタログ**を新設: `material`(steel/rc/wood)ごとに
  E [N/mm²]、G [N/mm²]、ρ [kg/m³] を持つ。既定値を組み込み
  (例: steel E=205000, G=79000, ρ=7850)、ユーザー編集可能にする。
- **断面特性**: 断面カタログの b/h から矩形断面として
  A [mm²]、Iy・Iz [mm⁴]、J [mm⁴] を算定してエクスポートに含める。
  H 形鋼等の非矩形はまず矩形近似とし、明示入力欄(上書き)を用意する。
- エクスポートの `sections` に `A, Iy, Iz, J`、`materials` 配列に
  `E, G, density` を追加。単位は units block に宣言する。

### D. ばね剛性値(P0)

- ばねカタログ(現状 `symbol` + `memo`)に剛性値を追加:
  回転ばね `kr [N·mm/rad]` を基本とし、並進 `kt [N/mm]` も任意入力可。
- 未入力(記号のみ)のばねは従来どおり許容するが、エクスポート時に
  「剛性未定義のばねを含む」警告フラグを `meta` に立てる
  (資料の停止原則:「推定して続行しない」に対応。下流 validator が検知できる)。

### E. 質量換算メタデータ(P0)

固有値解析用の質量源(自重・仕上げ・積載)を下流が組み立てられるよう、
荷重ケース→質量換算の定義をエクスポートに含める。

- `massSources`: 荷重ケースごとの質量換算係数(例: `DL: 1.0, LL: 0.3`)。
  既定値を持ち、エクスポート設定ダイアログ等で編集できる。
- 部材自重は材料 ρ×A×L で下流が算定できるため、二重計上を避けるための
  「自重は密度から算定/DL に含む」の別をフラグで明示する
  (資料 QA ゲート Q1「重力の二重計上」検査に対応)。

### F. 床区画情報(P1)

- 既存の面荷重(areaLoad)区画は矩形+レベルを持つため、これを
  床面矩形(`source_rect` 相当)として下流 adapter が使えるよう、
  区画の矩形・対象レベルをそのままエクスポート(現状も出力済み)し、
  仕様書で「床面区画の候補」として位置付ける。
- その上で、スラブ属性(厚さ・材料・仕上げ区分)を持つ独立した
  **床区画エンティティ**の追加を検討する。UI 負担が大きいため、
  A〜E 完了後に下流 adapter の要求仕様(INT-03 の `source_surfaces` /
  `source_rect`)を確認してから着手する。

## 3. 設計判断

### 3.1 変換(mm→m)は行わず、宣言を厳密にする

資料の責務分担どおり、SI 正規化は adapter 側で行う。element-modeler は
mm-N 系を維持し、**単位・座標系・質量換算前提を機械可読に宣言**することに
徹する。これにより既存のエクスポート利用者(v1 互換)への影響を最小化する。

### 3.2 format version は 2 に上げ、v1 フィールドは温存する

`id` の型が文字列→数値に変わるのは破壊的変更のため version を上げる。
それ以外の既存フィールドは維持し、追加のみとする。CSV も同様に
列追加+`sourceId` 列で対応する。

### 3.3 材料・断面の既定値は「試行値」と明示する

資料の禁止事項「試行結果を設計適合と読ませない」に合わせ、組み込み既定値は
UI・エクスポートの両方で既定値由来であることを示す(`isDefault` フラグ)。

## 4. 実装フェーズ

| フェーズ | 内容 | 主な変更ファイル |
|---|---|---|
| 1 | A+B: v2 採番・sourceId・meta 拡張(generator/coordinates/generatedAt) | `js/analysis-export.js`, `js/io.js` |
| 2 | C: 材料カタログ(state・UI・serialization)+断面特性算定・出力 | `js/state.js`, `js/section-catalog.js`, `js/analysis-export.js`, UI モーダル |
| 3 | D: ばねカタログ剛性値(state・UI)+警告フラグ | `js/state.js`, `js/user-def-modal.js` 等, `js/analysis-export.js` |
| 4 | E: massSources 設定+エクスポート | `js/analysis-export.js`, エクスポート設定 UI |
| 5 | ドキュメント整備: エクスポート仕様書(README または docs/)に v2 契約・単位・節点順・ID 規則を明記 | `README.md`, `docs/` |
| 6 | (P1)F: 床区画エンティティ — 下流 adapter 仕様の確定後に別計画で着手 | — |

各フェーズでテストを追加(現行 277 passed を維持):
- 数値 ID の一意性・`sourceId` 往復・X ブレース枝番
- 矩形断面特性の算定値(手計算と照合)
- 剛性未定義ばねの警告フラグ
- massSources 既定値と上書き
- v1→v2 の後方互換(既存フィールドの値が変わらないこと)

## 5. 受入条件(資料の受入条件との対応)

- [x] `M1`/`M2` を含むモデルが重複なく数値 ID 化され、元 ID を復元できる(INT-02)
- [x] エクスポート JSON に units・coordinates・generator・generatedAt が含まれ、
      下流 validator の「単位・ID・来歴」検査(資料 §4)に必要な情報が揃う(INT-01)
- [x] 使用中の全断面に A・Iy・Iz・J、全材料に E・G・ρ が出力される
- [x] 剛性未定義ばね・質量換算未設定が機械可読に検知できる(停止原則対応)
- [x] 既存テスト全通過+新規テスト追加、v1 利用箇所の互換確認

実施結果 (2026-08-08): フェーズ1〜5を実装し、JSON/CSV v2、CAD保存の
後方互換、材料・断面・ばね・質量源のUIを自動テストとブラウザで確認した。
フェーズ6の独立した床区画エンティティは、当初計画どおり下流adapterの仕様確定後に
別計画で扱う。

## 6. 本計画の位置付けと次段階

資料の実装開始順「1. schema・validator PR → 2. Test0202 復旧 PR →
3. 評価・TMD 連携 PR」のうち、本計画は **1 の element-modeler 側の前提整備**
に相当する。完了後、下流(Beam-TrussStructMaker 側 adapter、INT-02/INT-03)が
本エクスポートを読み込んで modal-ready bundle を生成する統合テスト(REG-01)へ
接続する。統合テスト自体は本リポジトリ外のため、別計画とする。
